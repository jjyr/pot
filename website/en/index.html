SECURITY & PERMISSIONSOS sandboxing, command approvals, and encrypted secrets

Clear boundaries for
autonomous assistants.

Clear boundaries come before autonomous work. Pot manages command permissions through machine execution policies, sandboxing and operation approvals. Keys are encrypted at rest and decrypted on demand.

01 / SYSTEM SANDBOX & POLICY

Commands run in the OS sandbox by default

🛡️ Protected ModeDefault for new nodes

Protected mode uses macOS Seatbelt or Linux bubblewrap by default: workspaces are writable, necessary toolchains are read-only, and unrelated personal files and control interfaces are restricted. Host exceptions follow execution policy and authorization.

⚡ Trusted ModeExplicit opt-in

If a node needs direct host execution, you can switch it to Trusted mode manually; explicit deny rules (deny_host) still block matching commands.

🚫 Blocked ModeKill switch

Immediately stops the node from starting new commands or editing files, allowing only log inspection and cleanup of existing processes.

02 / HOST EXECUTION APPROVAL

You approve anything outside the sandbox

When a task needs host access (such as pushing git tags over local SSH), the assistant explains why in chat and waits for your confirmation:

  • Exact command matchingEach approval binds the exact command and working directory (npm test and npm install are approved separately) with no wildcards.
  • Choose the approval scopeAllow for the current task only (revoked when the task finishes), always allow that exact command, or deny.
  • Separate permissions per machineAgents connected through Agent Link retain their own permissions. Explicitly delegated Codex tasks can relay pending human approvals; Antigravity headless mode cannot forward interactive approvals.

03 / SECRET ENCRYPTION & IN-MEMORY DECRYPTION

Secrets stay encrypted at rest and decrypt only in memory

KEYCHAIN / 0600

Separate master key storage

The master key is never stored in the database. It lives in the macOS Keychain or a user-only (0600) key file on Linux.

AES-256-GCM

Encrypted in local storage

API keys and OAuth tokens are encrypted with AES-256-GCM before being written to SQLite. Settings and UI views reference only ciphertext IDs.

IN-MEMORY USE

Decrypted in memory on demand

Model requests and credential injection decrypt keys on demand; the UI and tools reference credential IDs. Authorized processes may access injected credentials, so choose tools and execution scopes carefully.

v0.0.4 ↗2026-10-27Latest Release

Pot 0.0.4 — Offline startup, chat recovery and local drafts

  • Reopen an installed PWA from its complete cached shell, assistant directory, conversations, reading position and drafts while runtime checks run in the background.
  • Restore one local draft per assistant (including text, references and original attachment files) and continue interrupted turns from the composer button.
  • Recover stalled browser chat streams and cancelled access probes; unify local file delivery, add lifecycle notifications and optional PWA Web Push.
  • Repair native update simulation discovery and preserve writable Task workspaces when the Runtime state root uses a filesystem alias.
v0.0.3 ↗2026-10-26

Pot v0.0.3 — Conversation continuity, committed data reads and update discovery

  • Chat and Task views share a conversation list controller that preserves reading position and stable message anchors while scrolling, refreshing, and loading older history.
  • Frontend views render committed local data through shared repositories and bounded queries, revoking stale menu actions before execution.
  • Updates are easier to discover from shared navigation and Settings, with migration lineage validation and transactional database migration batches.
v0.0.2 ↗2026-10-25

Pot 0.0.2 — Assistant setup, Agent connections, task continuity and desktop updates

  • Create assistants directly on existing Runtime connections with guided Codex and Antigravity setup, and add Antigravity Agent Link support.
  • Bind Task continuation to its original workspace and Git association so resumed work retains context, and preserve the latest chat messages when switching assistants.
  • Repair the native macOS App update lifecycle and add an independent macOS Homebrew CLI Formula (pot-cli).
v0.0.1 ↗2026-10-24

Pot 0.0.1 — Initial release

  • Persistent assistant conversations, asynchronous background Tasks, Cron schedules, and GitHub notification routing.
  • Agent Link peer-to-peer collaboration with verified Codex session and task delegation.
  • SRT native sandboxing (macOS Seatbelt and Linux bubblewrap), exact command approvals, and AES-256-GCM encrypted secret storage.
