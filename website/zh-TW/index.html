沙箱隔離、精確命令審批
與金鑰加密機制。

背景自動執行任務需要明確的權限邊界與憑據隔離。Pot 在控制層透過系統沙箱限制檔案與網路存取，對宿主機命令實施精確比對審批，並將所有金鑰加密儲存、僅在呼叫時於記憶體中解密。

01 / MACHINE POLICY & SRT SANDBOX

機器執行策略與 SRT 原生沙箱

🛡️ Protected（受保護 · 預設）新節點預設

命令預設在 SRT 原生沙箱（macOS Seatbelt 或 Linux bubblewrap / seccomp）內運行。僅目前任務工作區可寫，系統工具鏈唯讀，屏蔽使用者隱私目錄、執行期控制設定與無關 Socket。

⚡ Trusted（信任宿主機）顯式開啟

由節點擁有者顯式切換後，允許命令跳過沙箱直接在宿主機執行。但顯式設定的 deny_host 拒絕規則始終優先並攔截符合命令。

🚫 Blocked（全面封鎖）緊急熔斷

禁止該機器啟動任何新命令或檔案修改操作，覆蓋已有授權規則，僅允許讀取已運行行程的輸出與執行清理。

02 / ZERO-WILDCARD APPROVALS

無萬用字元命令審批

當任務需要跳出沙箱執行（request_unsandboxed: true）時，需說明原因並等待人工審批。權限規則不支援前綴比對或萬用字元：

  • 完整上下文綁定永久授權規則同時綁定完整命令字串、規範化工作目錄 (cwd)、Shell、互動模式與憑據引用。npm test、npm install 與 npm test && curl 均視為不同命令，必須分別審批。
  • 三種審批範圍支援 allow_always（本機記住該精確命令組合）、allow_task（僅目前任務有效，任務結束即失效）與 deny（拒絕執行）。
  • 跨節點權限隔離Agent Link 連接不會向遠端授予本機執行權；委派給遠端 Codex 的任務若觸發審批，請求會回傳至目前對話由你確認。

03 / ENCRYPTED SECRETS & ON-DEMAND DECRYPTION

加密保管與僅使用時記憶體解密

KEYCHAIN / 0600

主金鑰與資料庫分離

加密主金鑰不寫入資料庫。macOS 儲存於系統 Keychain（pot.control.secrets）；Linux 儲存於權限為 0600 的獨立金鑰檔案或透過 POT_SECRET_KEY_FILE 注入。無法安全取得主金鑰時直接報錯，不降級為明文。

AES-256-GCM

靜態加密儲存

API Key 與 OAuth 權杖在寫入 SQLite 前均使用 AES-256-GCM（每次寫入產生獨立 96-bit Nonce）加密。設定表與管理介面僅保存和回傳不可變的 secret_ref 引用，不回傳明文。

ON-DEMAND DECRYPT

僅在使用瞬間解密注入

金鑰平時始終以密文存放，不進入 Prompt、聊天記錄或日誌。僅在發起模型請求，或啟動宣告了憑據引用的子行程瞬間，控制層才在記憶體中解密並透過瞬態環境變數注入行程，行程退出後立即釋放。
