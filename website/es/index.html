SECURITY & PERMISSIONSSandbox del sistema, confirmación de comandos y claves cifradas

Límites claros para
delegar con tranquilidad.

Los límites claros son la base del trabajo autónomo. Pot gestiona los permisos mediante políticas de ejecución, aislamiento y aprobaciones. Las claves se almacenan cifradas y se descifran cuando se necesitan.

01 / SYSTEM SANDBOX & POLICY

Los comandos corren en el sandbox por defecto

🛡️ Modo protegido (Protected)Predeterminado en nodos nuevos

El modo protegido usa macOS Seatbelt o Linux bubblewrap: permite escribir en el espacio de trabajo, leer las herramientas necesarias y restringe archivos personales e interfaces de control ajenos. Las excepciones de ejecución en el host dependen de la política y la autorización.

⚡ Modo de confianza (Trusted)Activación explícita

Si necesitas que un nodo ejecute comandos directamente en la máquina, puedes cambiarlo manualmente; las reglas explícitas de bloqueo (deny_host) siguen activas.

🚫 Modo bloqueado (Blocked)Interruptor de corte

Detiene al instante cualquier comando nuevo o cambio de archivos en ese nodo, permitiendo solo ver salidas activas y limpiar procesos.

02 / HOST EXECUTION APPROVAL

Tú apruebas lo que salga del sandbox

Cuando una tarea necesita acceso al sistema (como usar SSH local para git push), el asistente explica el motivo y espera tu confirmación:

  • Confirmación por comando exactoCada permiso se vincula al comando y directorio exactos (npm test y npm install se aprueban por separado), sin comodines.
  • Elige el alcance del permisoPermite solo para la tarea actual, siempre para ese comando exacto, o recházalo.
  • Permisos independientes por equipoLos agentes conectados conservan sus permisos. Las tareas delegadas explícitamente a Codex pueden transmitir aprobaciones humanas pendientes; el modo sin interfaz de Antigravity no permite transmitir aprobaciones interactivas.

03 / SECRET ENCRYPTION & IN-MEMORY DECRYPTION

Las claves se guardan cifradas y solo se descifran al usarse

KEYCHAIN / 0600

Clave maestra separada

La clave maestra nunca se guarda en la base de datos: reside en el Llavero de macOS o en un archivo 0600 independiente en Linux.

AES-256-GCM

Guardadas siempre cifradas

Tus API Keys y tokens se cifran con AES-256-GCM antes de guardarse en SQLite. La interfaz solo maneja referencias cifradas.

IN-MEMORY USE

Descifrado temporal en memoria

Las claves se descifran cuando lo requieren las solicitudes al modelo o la inyección de credenciales; la interfaz y las herramientas usan sus identificadores. Los procesos autorizados pueden acceder a las credenciales inyectadas: elige con cuidado las herramientas y su alcance.

v0.0.4 ↗2026-10-27Latest Release

Pot 0.0.4 — Offline startup, chat recovery and local drafts

  • Reopen an installed PWA from its complete cached shell, assistant directory, conversations, reading position and drafts while runtime checks run in the background.
  • Restore one local draft per assistant (including text, references and original attachment files) and continue interrupted turns from the composer button.
  • Recover stalled browser chat streams and cancelled access probes; unify local file delivery, add lifecycle notifications and optional PWA Web Push.
  • Repair native update simulation discovery and preserve writable Task workspaces when the Runtime state root uses a filesystem alias.
v0.0.3 ↗2026-10-26

Pot v0.0.3 — Conversation continuity, committed data reads and update discovery

  • Chat and Task views share a conversation list controller that preserves reading position and stable message anchors while scrolling, refreshing, and loading older history.
  • Frontend views render committed local data through shared repositories and bounded queries, revoking stale menu actions before execution.
  • Updates are easier to discover from shared navigation and Settings, with migration lineage validation and transactional database migration batches.
v0.0.2 ↗2026-10-25

Pot 0.0.2 — Assistant setup, Agent connections, task continuity and desktop updates

  • Create assistants directly on existing Runtime connections with guided Codex and Antigravity setup, and add Antigravity Agent Link support.
  • Bind Task continuation to its original workspace and Git association so resumed work retains context, and preserve the latest chat messages when switching assistants.
  • Repair the native macOS App update lifecycle and add an independent macOS Homebrew CLI Formula (pot-cli).
v0.0.1 ↗2026-10-24

Pot 0.0.1 — Initial release

  • Persistent assistant conversations, asynchronous background Tasks, Cron schedules, and GitHub notification routing.
  • Agent Link peer-to-peer collaboration with verified Codex session and task delegation.
  • SRT native sandboxing (macOS Seatbelt and Linux bubblewrap), exact command approvals, and AES-256-GCM encrypted secret storage.
