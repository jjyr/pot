SECURITY & PERMISSIONS系统沙箱隔离、宿主机执行确认与密钥加密存储

沙箱运行边界
与密钥安全保管。

为了让助手能够安全地自动推进任务，Pot 默认在系统沙箱中运行命令，对需要访问宿主机的操作要求人工确认，并将所有 API 密钥加密存储、仅在调用时于内存中解密。

01 / SYSTEM SANDBOX & POLICY

默认在系统沙箱中隔离运行

🛡️ Protected（沙箱保护 · 默认）新节点默认

命令默认在原生系统沙箱（macOS Seatbelt 或 Linux bubblewrap / seccomp）中运行。仅当前任务的工作区目录可写，系统工具链只读，隔离个人目录与无关系统配置。

⚡ Trusted（宿主机直连）显式开启

由节点所有者手动开启后，允许命令跳过沙箱直接在宿主机运行；但显式配置的拒绝规则（deny_host）依然优先并拦截匹配命令。

🚫 Blocked（暂停执行）紧急熔断

立即禁止该节点启动任何新命令或修改文件，仅保留对已运行进程的输出查看与清理。

02 / HOST EXECUTION APPROVAL

跳出沙箱时，在对话中由你确认

当后台任务确实需要访问宿主机环境（例如调用本机 SSH 推送代码）时，助手会说明原因并发起权限申请，确认后才会执行：

  • 按具体命令与目录授权授权记录绑定具体的命令内容与工作目录（例如 npm test 与 npm install 会分别确认），避免一次授权被其他命令复用。
  • 灵活选择授权范围可选择「仅本次任务允许」（任务结束后自动失效）、「始终允许此命令」，或直接拒绝执行。
  • 跨设备权限各自独立通过 Agent Link 连接外部节点时，不会共享本机执行权限；远端 Codex 触发的确认请求会回传到当前对话中处理。

03 / SECRET ENCRYPTION & IN-MEMORY DECRYPTION

密钥加密保存，仅在使用时解密

KEYCHAIN / 0600

主密钥独立存放

用于加解密的主密钥不写入数据库。macOS 保存在系统 Keychain（pot.control.secrets），Linux 保存在权限为 0600 的独立密钥文件或由环境变量指定。

AES-256-GCM

数据库密文存储

所有模型 API Key 与第三方令牌均通过 AES-256-GCM 加密后写入 SQLite。业务配置与接口只记录密文引用（secret_ref），不返回明文。

IN-MEMORY USE

仅在调用时内存解密

密钥平时始终以密文保存，不会进入模型 Prompt、聊天记录或日志。仅在发起模型请求、或启动需要该凭据的子进程时，才在内存中临时解密注入，进程结束后立即释放。
