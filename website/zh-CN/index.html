沙箱隔离、精确命令审批
与密钥加密机制。

后台自动执行任务需要明确的权限边界与凭据隔离。Pot 在控制层通过系统沙箱限制文件与网络访问，对宿主机命令实施精确匹配审批，并将所有密钥加密存储、仅在调用时于内存中解密。

01 / MACHINE POLICY & SRT SANDBOX

机器执行策略与 SRT 原生沙箱

🛡️ Protected（受保护 · 默认）新节点默认

命令默认在 SRT 原生沙箱（macOS Seatbelt 或 Linux bubblewrap / seccomp）内运行。仅当前任务工作区可写，系统工具链只读，屏蔽用户隐私目录、运行时控制配置与无关套接字。

⚡ Trusted（信任宿主机）显式开启

由节点所有者显式切换后，允许命令跳过沙箱直接在宿主机执行。但显式配置的 deny_host 拒绝规则始终优先并拦截匹配命令。

🚫 Blocked（全面封锁）紧急熔断

禁止该机器启动任何新命令或文件修改操作，覆盖已有授权规则，仅允许读取已运行进程的输出与执行清理。

02 / ZERO-WILDCARD APPROVALS

无通配符命令审批

当任务需要跳出沙箱执行（request_unsandboxed: true）时，需说明原因并等待人工审批。权限规则不支持前缀匹配或通配符：

  • 完整上下文绑定永久授权规则同时绑定完整命令字符串、规范化工作目录 (cwd)、Shell、交互模式与凭据引用。npm test、npm install 与 npm test && curl 均视为不同命令，必须分别审批。
  • 三种审批范围支持 allow_always（本机记住该精确命令组合）、allow_task（仅当前任务有效，任务结束即失效）与 deny（拒绝执行）。
  • 跨节点权限隔离Agent Link 连接不会向远端授予本机执行权；委派给远端 Codex 的任务若触发审批，请求会回传至当前对话由你确认。

03 / ENCRYPTED SECRETS & ON-DEMAND DECRYPTION

加密保管与仅使用时内存解密

KEYCHAIN / 0600

主密钥与数据库分离

加密主密钥不写入数据库。macOS 存储于系统 Keychain（pot.control.secrets）；Linux 存储于权限为 0600 的独立密钥文件或通过 POT_SECRET_KEY_FILE 注入。无法安全获取主密钥时直接报错，不降级为明文。

AES-256-GCM

静态加密存储

API Key 与 OAuth 令牌在写入 SQLite 前均使用 AES-256-GCM（每次写入生成独立 96-bit Nonce）加密。配置表与管理接口仅保存和返回不可变的 secret_ref 引用，不回传明文。

ON-DEMAND DECRYPT

仅在使用瞬间解密注入

密钥平时始终以密文存放，不进入 Prompt、聊天记录或日志。仅在发起模型请求，或启动声明了凭据引用的子进程瞬间，控制层才在内存中解密并通过瞬态环境变量注入进程，进程退出后立即释放。
